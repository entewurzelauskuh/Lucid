# LUCID — Design history

How the design got here, one line per spec version. The consolidated documents supersede all of it; this file exists so a contributor can see which decisions were taken in which order and why the defaults look the way they do. File names mentioned in the entries are the working titles of the time; the consolidated set uses the repository paths listed in `SPEC.md` §21.

- **v0.1** — First draft: asymmetric loop (Architect vs Runners), lobby, timed rounds, budget, any open face as the exit, materialize window, MVP cell list, milestones.
- **v0.2** — combat model and the Nightlight weapon (§8); mobs, turrets and trap weak points (§7); Nightmare live powers: manual triggers, possession, global effects (§9); movement kit settled; friendly fire removed; power toggles in lobby settings; tech notes for hit registration and possession (§13); open questions trimmed (§14); milestones re-cut (§15).
- **v0.3** — engine is Unity (§14 rewritten); the exit is now the deepest cube's fog doors, not any open face (§7); fog-door states and the *explored* mechanic that solidifies unused connectors (§7); placement is instant, materialize window removed; every Sleeper runs in their own parallel dream (§5); 1–4 Sleepers; Nightmare powers defined across dreams (§10); woken Sleepers spectate only; future parking lot (§16); milestones re-cut (§17).
- **v0.4** — depth = path length settled (§7); each dream is simulated on its Sleeper's own machine, tech section rewritten around that (§5, §14); Nightmare target selector for triggers and effects, default All (§10); possession specified as remote control across clients (§14); open questions trimmed (§15).
- **v0.5** — art direction, the dream filter over realistic-ish free assets (§15); content strategy with Dream Packs (§16); cube authoring pipeline for Claude Code (§17); Steam from the start, Facepunch transport, lobbies and invites (§14); input devices, gamepad for Sleepers (§9, §14); lobby settings for packs and aim assist (§6); milestones re-cut around the pipeline (§20).
- **v0.6** — Dream Packs ship as free updates in the base build (§16); open source on GitHub, with the asset-redistribution rule, the contribution path and a Steam-free dev mode (§18); dev loop notes (§14); milestones moved to the separate work plan, `lucid-workplan-v0.1.md` (§21); open questions re-cut (§19).
- **v0.7** — code license MIT, original content CC-BY-4.0 (§18); tests run locally only, no CI for now (§18); every change is a pull request reviewed by the owner (§18); open questions trimmed (§19); companions are now `lucid-workplan-v0.2.md` and the `CLAUDE.md` draft (§21).
- **v0.8** — UI screens and flows moved to a companion document, `lucid-ui-v0.1.md` (§21a); Nightmare hotkeys revised so the number row serves the palette and Tab cycles the power target (§10); audio is SFX first, music later (§15a); no in-game voice or text chat, friends use Discord (§18); sandbox mode as a dev tool (§14); open questions trimmed (§19).
- **v0.9** — Nightmare key map settled (§10); sandbox settled (§14); cube spec schema and `Lucid.Core` API published as companions, `cube-spec.schema.json`, `lucid-cube-spec-v0.1.md`, `lucid-core-api-v0.1.md` (§21b); open question 5 closed.
- **v0.10** — chicane component library published as `lucid-chicanes-v0.1.md` (§21c); the three laws of traps adopted as defaults (§8); Core API accepted as written (§14).
- **v0.11** — the three laws of traps settled (§8); netcode message catalogue published as `lucid-netcode-v0.1.md` (§21d); NGO server time adopted as the round clock and dream-view subscriptions as the one mechanism for spectating and possession (§14).
- **v0.12** — M0 playtest plan published as `lucid-playtest-m0-v0.1.md` (§21e); the tuning console and log report added to the work plan as M0.9c.
- **v1.0** — Consolidation pass: version-suffixed cross-references replaced by repository paths, section numbering cleaned up, small inconsistencies fixed (Pendulum trigger is `hold`; TimedSpikes parameters in milliseconds; `WakeVerdict` carries a reason), changelogs moved here.

Design decisions taken during implementation go in `DECISIONS.md`, not here.
